# StreetBuddy — архитектура

Пометки в квадратных скобках показывают состояние кода: `[сделано]`, `[нет]`, `[частично: что не сделано]`, `[справочный]` (описание формы или шаг человека, кода нет).

## Цель

StreetBuddy — Telegram-бот, который превращает фото нарушения в заполненную форму [Traffic Watch](https://www.garda.ie/en/trafficwatchreport/); человеку остается поставить две галочки, пройти капчу и нажать «Submit Report».

1. [сделано] Бот доступен только участникам закрытой Telegram-группы: он проверяет членство пользователя в группе (для этого бот добавлен в группу администратором), а не участникам отвечает, что бот только для участников группы (текст: «This bot is only for members of the group»; на нажатие «Yes, it’s correct» не участником — всплывающее уведомление с тем же текстом и без ссылки, черновик остается; исключение — /admin, на который не администратор не получает никакого ответа, п.76). Интерфейс на английском, для пользователей iPhone и Android; работает в одном районе на северо-востоке Дублина (пункты 66–69).
2. [сделано] Бот работает только с нарушением «Parking Offences» (нелегальная парковка); остальные типы нарушений из формы не поддерживаются.
3. [сделано] Бот не отправляет форму сам и не обходит капчу: последний шаг всегда делает человек.
4. [сделано] Бот ни с кем не аффилирован; в названии и логотипе нет слов, указывающих на связь с госорганами.

## Форма Traffic Watch и откуда берутся данные

Форма — обычная страница Traffic Watch без фреймов (во фрейме только капча Google); все поля, кроме галочек и капчи, заполняет скрипт.

| Поле формы | id на странице | Откуда значение |
| --- | --- | --- |
| I confirm that this is not an emergency | NotAnEmergencyCheckbox | пользователь ставит сам |
| I confirm that I am willing to make a statement and attend Court | AttendCourtCheckbox | пользователь ставит сам |
| Click Here to Start | startBtn | пользователь нажимает сам; после этого появляются поля |
| Address or general location (текст) | Location | бот: адрес и GPS-координаты в виде `<адрес> (53.40123, -6.14567)`, 5 знаков |
| County (26 графств) | County | бот: из настроек района (Dublin) |
| Type of crime/incident (12 вариантов) | Crime | скрипт: всегда «Parking Offences» |
| Were you a (6 вариантов: Cyclist; Driver; E-Scooter User, E-Moped User, E-Cyclist; Motorcyclist; Passenger; Pedestrian) | RoadUserType | бот: пользователь выбирает кнопками (п.22) |
| Description | CrimeDescription | бот: шаблон по типу нарушения |
| Date (дд/мм/гггг) | crimeDate_1 | бот: дата отправки первого фото |
| First Name and Last Name (одно поле) | UserName | скрипт: сохранено на телефоне |
| Phone | Phone | скрипт: сохранено на телефоне |
| Email | Email | скрипт: сохранено на телефоне |
| Address | UserAddress | скрипт: сохранено на телефоне |
| How you wish to be contacted (Email / Phone Call / Text Message) | ContactMethod | скрипт: сохранено на телефоне |
| I'm not a robot | reCAPTCHA | пользователь |
| Submit Report | submitReport | пользователь |

[сделано] Скрипт заполняет все поля таблицы, кроме галочек, кнопок и капчи; значения для Location, County, Were you a, Description и Date готовит бот.

5. [справочный] Фото и видео в форму загрузить нельзя; их передают в Traffic Watch позже, по запросу.
6. [сделано] Описание — до 300 символов: так указано в тексте формы; страница это не проверяет, бот держит лимит сам.
7. [справочный] Репорт можно подать не позже 6 месяцев после нарушения; календарь даты раньше не пускает.
8. [сделано] Отдельного поля времени нет: время нарушения входит в описание.
9. [справочный] Форма не для экстренных случаев и обрабатывается не круглосуточно.
10. [справочный] Подтверждение с номером обращения приходит только на email.
11. [справочный] Сайт не использует часть ссылки после `#`; защита страницы запрещает только встраивание в чужие сайты и не мешает закладке и юзерскрипту.

## Пользовательский сценарий

Один репорт занимает около минуты: место, фото, два-три касания в боте, затем галочки, капча и кнопка на сайте Traffic Watch.

Один раз, при первом использовании:

12. [частично: страницы политики приватности нет, вместо ссылки на нее стоит временная строка] Команда /start показывает текст ниже; слова «manual» и «Installation guide» в нем — ссылки на страницы руководства и установки (бот отправляет текст как HTML и отключает предпросмотр ссылок):

```
StreetBuddy turns a photo of an illegally parked car into a pre-filled Garda Traffic Watch report form. You tick the two boxes, pass the captcha and press Submit yourself.
Please note: a report may require you to give a statement in court.
***
First, read the manual.
Second, set up your phone: Installation guide.
Third, to start a report, send location to the bot.
***
This bot is not affiliated with An Garda Síochána.
(A link to the Privacy Policy will be here.)
© OpenStreetMap contributors
```

Строка про политику приватности временная: когда страница политики появится (п.58), ее заменит строка со ссылкой. /start посреди репорта останавливает его молча, как все команды меню (п.17).
13. [частично: на реальном iPhone не проверено] Пользователь ставит скрипт: Android — закладка в Chrome; iPhone — закладка в Safari.
14. [справочный] Пользователь настраивает Telegram так, чтобы ссылки открывались во внешнем браузере (на iPhone — Safari в настройках Telegram), или каждый раз выбирает «Open in browser».
15. [сделано] Пользователь вводит личные данные (имя, телефон, email, адрес, способ связи) один раз: их вводят на странице инструкции, и страница прямо в браузере собирает закладку с этими данными внутри — на сервер ничего не уходит.

Каждый репорт:

16. [сделано] Репорт всегда начинается с геолокации: пользователь присылает ее (скрепка → «Location», там можно поставить точку на карте). Поиска адреса по тексту нет: на текст вместо геолокации бот отвечает «Please send the location». Постоянной кнопки «Location» внизу чата нет, все кнопки бота — инлайн. Новая геолокация на любом шаге начинает репорт заново: старый черновик и экран с кнопками удаляются без «Report cancelled»; пока бот выключен (п.46), новый репорт не начинается и старый остается как есть. Фото, присланное до места, бот молча игнорирует и не запоминает.
17. [сделано] Как только бот пишет новое сообщение с кнопками, предыдущее сообщение с кнопками удаляется. «Cancel» есть на всех шагах: бот останавливает репорт, удаляет черновик и сообщение с кнопками, остальная переписка остается, и пишет «Report cancelled» без кнопок. На итоговом сообщении (п.24) «Cancel» и «Done» работают иначе, а команда /admin останавливает начатый репорт молча (п.76). Кнопки не остаются в середине разговора: на любое сообщение пользователя, которого бот на этом шаге не ждет (текст, фото, файл), он отправляет текущий экран заново, а старый удаляет; исключение — момент выдачи ссылки, когда экран и так сразу исчезает. Текст репорт не начинает (п.16). Любая команда (/start и команды меню, п.84) останавливает репорт молча, как /admin (п.76). Экраны с кнопками, у которых нет своего черновика (главный экран /admin, экран одного входящего адреса вместе с его пином, `Choose the kind`, экран адреса, списки номеров `Repeat plates` и `Possibly abandoned cars`, `Report map` и страницы `/hotspots`), бот запоминает в черновике с шагом `screen`: команда меню удаляет такой экран вместе с кнопками. Пока есть черновик репорта или другого экрана /admin (не старше 24 часов), `screen` его не заменяет; геолокация при открытом `screen` удаляет этот экран вместе с его пинами и начинает репорт. Сообщения «Report map» с кнопкой «Open map», присланные кнопками периодов, запоминаются вместе с экраном `Report map`, и команда удаляет их все; кнопка периода работает только на запомненном экране `Report map` и на его меню после первого нажатия; кнопка другого, старого экрана `Report map` только снимает «часики». Нажатие старой кнопки только снимает «часики». При сбоях Nominatim из п.18 на сообщении тоже есть «Cancel».
18. [сделано] Бот проверяет, что место внутри района. Если нет, бот отвечает «Sorry, this bot doesn't work in this area» и дальше не идет. Nominatim бот спрашивает только тогда, когда в пределах 30 м нет ни одного адреса справочника (п.97); если Nominatim адрес не нашел, бот показывает экран выбора адреса (п.19) только с кнопками «Other address» и «Cancel». При первом сбое Nominatim бот отвечает «Could not get the address. Please try again in a minute» При втором сбое — «Could not get the address. Please write it»: координаты уже есть, район проверяется без Nominatim, текст сохраняется как есть и при выдаче ссылки попадает во входящие адреса (п.99); после него бот сразу переходит к фото (п.20).
19. [сделано] В каждом репорте бот показывает экран выбора адреса: сообщение «Choose the address» и кнопки по одной в ряду в таком порядке: до двух ближайших адресов справочника в пределах 30 м любой формы, в том числе территории (п.97), ближайший первым, «Other address», «Cancel». На кнопках адрес без почтового района (п.33). Адрес Nominatim стоит кнопкой перед «Other address» только тогда, когда в пределах 30 м нет ни одного адреса справочника. Нажатие на вариант сразу подтверждает адрес и ведет к фото (п.20). По «Other address» бот пишет «Write the address»; на текст из одних пробелов бот спрашивает снова; введенный текст (до 100 символов, иначе «The address must be 100 characters or less») сохраняется как есть, координаты — из геолокации, и бот сразу переходит к фото; при выдаче ссылки адрес попадает во входящие адреса (п.99). Фото до выбора адреса игнорируется, а экран выбора удаляется и отправляется заново под фото.
20. [сделано] После выбора адреса бот пишет «Send photos, the first one with the number plate, or write the plate number» Вместо фото можно написать номер машины текстом (п.91). Пользователь отправляет фото по одному или альбомом, лимита на их число нет. На каждое фото бот отвечает «Photo received. Send more photos or press Create report» с кнопками «Create report» и «Cancel» в одном ряду; на альбом отвечает один раз: Telegram не отмечает последнее фото альбома, поэтому бот ждет 2 секунды после очередного фото. Фото файлом (документом) бот не принимает; на него и на текст бот заново отправляет текущий экран (п.17). Номер машины распознается в фоне сразу после первого фото; остальные фото показывают расположение машины.
21. [сделано] По «Create report» бот показывает один экран с номером и временем: кнопки «Confirm», «Edit plate», «Change time», «Cancel». Если на первом фото несколько машин, сначала бот показывает все распознанные номера кнопками («Several plates found. Choose one») и кнопку «Add» для ввода своего номера (в одном ряду с «Cancel»), и пользователь выбирает нужный. Если распознавание еще идет, бот дожидается его. Текст экрана — две строки: `Plate: 12-D-3456` и `Time: 02/11/2026 13:02`. Время по умолчанию — момент отправки первого фото. По «Edit plate» бот присылает прежний номер, пустую строку и «Write the plate number»; номер до 15 символов, иначе «The plate number is too long. Please write it again». По «Change time» бот присылает прежнее время, пустую строку и «Write the time as hh:mm»; меняется только время, дата — всегда дата первого фото; неверное время и время позже текущего не принимаются: «Wrong time. Please write it again»
22. [сделано] Пользователь выбирает один или несколько вариантов парковки кнопками-переключателями (касание ставит или снимает ✅) и нажимает «Done»; текст сообщения — «Choose one or more options, then press Done». Нужен хотя бы один вариант, иначе всплывающее уведомление «Choose at least one option». «Done» и «Cancel» стоят в одном ряду под вариантами. Кнопки: «on a cycle track», «on a footpath», «on a grass margin», «within 5m of a junction», «blocking a private driveway», «interfering with traffic flow», «obstructing and endangering traffic». После «Done» бот спрашивает «Were you a:» (поле формы RoadUserType) кнопками с шестью вариантами формы в таком порядке: «Pedestrian», «Passenger», «Driver», «Cyclist», «Motorcyclist», «E-Scooter User, E-Moped User, E-Cyclist» — и «Cancel» отдельной строкой; касание варианта ведет к экрану проверки (п.90).
23. [сделано] Бот составляет описание по шаблону и показывает его на экране проверки (п.90). Свободного текста в описании нет: на экране Edit меняются его части.
24. [сделано] После «Yes, it’s correct» (и ответа на `Your phone?`, п.92) бот удаляет все свои промежуточные сообщения и сообщения пользователя, отправленные в ходе диалога (геолокация, адрес, исправления), кроме фото, и отправляет итоговое сообщение реплаем на последнее фото, а если фото нет — обычным сообщением: описание нарушения (п.35), разбитое на строки: `Vehicle <номер>`, каждый выбранный вариант парковки на своей строке (`parked …`; при нескольких вариантах запятая в конце каждой строки, кроме последних двух, и «and» в начале последней), `at <адрес>`, `on <дата> at <время>.`; адрес тот же, что в описании формы: с почтовым районом по п.33 и при сокращении по п.35 сокращен так же; затем строка о выбранном варианте «Were you a», например `I was a pedestrian.` (п.90). Затем пустая строка, шаги для выбранного телефона (п.92) и кнопки: ряд с кнопкой-ссылкой «Open report» и под ним в одном ряду «Done» и «Cancel». В переписке остаются фото и итоговое сообщение под ними. «Cancel» удаляет только это сообщение вместе с кнопками, фото остаются, и строку этого репорта в журнале (п.89): репорт не считается; адрес, записанный во входящие при выдаче ссылки (п.99), остается. «Done» убирает все кнопки, включая «Open report», а шаги заменяет на `Report sent 03/11/2026 10:35`: дата и время нажатия «Done», по Дублину. Строка журнала репортов (п.89) пишется при выдаче ссылки, и «Done» ее не меняет. Для этого текст отчета без шагов хранится в D1 (с ID чата и сообщения, а также ID строки журнала) до нажатия «Done» или «Cancel», но не дольше 48 часов. Через 48 часов (ближайший запуск по расписанию, п.47, до 30 сообщений за запуск) бот убирает кнопки и шаги, оставляет описание, строку `Report sent` не пишет, журнал не меняет; текст стирается из D1 только после того, как Telegram изменил сообщение, а оставшиеся к концу запуска стираются очисткой (п.61). Новый репорт старые итоговые сообщения не затрагивает: их кнопки работают до срока. Если текста уже нет, «Done» только убирает кнопки, а «Cancel» удаляет сообщение.
25. [справочный] Пользователь открывает ссылку в браузере, сам ставит две галочки и нажимает «Click Here to Start».
26. [сделано] Скрипт заполняет все поля (в Chrome — после касания закладки); пользователь проверяет данные, проходит капчу и нажимает «Submit Report».
27. [справочный] Traffic Watch присылает email с номером обращения.

## Функциональные требования

Бот собирает данные о нарушении и упаковывает их в ссылку; скрипт распаковывает ссылку в поля формы.

Бот:

28. [сделано] Язык интерфейса — английский. Сообщения бота из одного предложения не заканчиваются точкой, у сообщений из нескольких предложений точки нет только в конце; описание нарушения (п.35) и последняя строка итогового сообщения (п.24) с точкой.
29. [сделано] Сначала проверяется место, потом распознается номер, чтобы фото из чужого района не тратили лимит; поэтому репорт начинается с места.
30. [сделано] Номер распознает модель Workers AI, понимающая изображения, без лицензионного запрета для ЕС (кандидаты по порядку — Gemma 4 26B A4B, Gemma 3 12B, Mistral Small 3.1 24B); модель выбирается по проверке на реальных ирландских номерах; сейчас стоит Gemma 4 26B A4B (`@cf/google/gemma-4-26b-a4b-it`). Если распознать не удалось, бот пишет «Could not read the plate. Please write it.» Llama 3.2 Vision и Llama 4 Scout не используются: их лицензия не дает прав разработчику, живущему в ЕС.
31. [сделано] Одно и то же фото не распознается повторно: результат хранится по постоянному ID файла в Telegram.
32. [сделано] Если дневной лимит Workers AI исчерпан или распознать номер не удалось, бот просит ввести номер вручную.
33. [сделано] Адрес определяется по справочнику адресов, куда входят и территории (п.93–102); OpenStreetMap Nominatim спрашивается только по геолокации и только когда в пределах 30 м нет ни одного адреса справочника; результаты Nominatim кешируются (координаты для кеша округляются до 4 знаков, около 10 м); графство берется из настроек района. Вид адреса Nominatim: дом, улица, район и eircode, например `12 Main Street, Clongriffin, D13 X1Y2`; если полного eircode в OSM нет — без него: `12 Main Street, Clongriffin`. Почтовый район из настроек района (D13) нигде не хранится: ни в справочнике, ни во входящих, ни в кеше Nominatim, ни в журнале. Бот дописывает его (`Parkside Drive, D13`) только в поля Location и Description формы и в итоговое сообщение (п.24), и только если в адресе нет eircode; на кнопках, на экране проверки, в журнале и в /hotspots адрес без него. С конца адреса, написанного пользователем, бот убирает почтовый район.
34. [сделано] Тип нарушения в форме всегда «Parking Offences»; кнопки бота — семь вариантов парковки из п.22.
35. [сделано] Шаблон описания на английском до 300 символов: номер машины, выбранные варианты парковки (через запятую, перед последним — «and»), место, дата и время. Если текст длиннее 300 символов, бот сокращает адрес в описании: убирает части с конца по запятой, а если этого мало, обрезает оставшуюся; полный адрес остается в поле Location. ## Приватность и безопасность

Имя, телефон, email и адрес пользователя не попадают на сервер бота; место, фото и Telegram ID попадают и обрабатываются, как описано ниже.

58. [нет] Оператор бота — владелец проекта. Нужна полноценная политика приватности: кто оператор и как с ним связаться, какие данные обрабатываются (Telegram ID, имя и @username в закрытой группе, фото, место, номер машины), основание обработки, сроки хранения, сторонние сервисы (Telegram, Cloudflare, OpenStreetMap, Mapbox), удаление данных по запросу. До публичного запуска — оценить, нужна ли DPIA.

Сообщения и фото остаются в чате пользователя и на серверах Telegram — это указано в политике. Когда пользователь запускает закладку, Worker получает запрос на файл скрипта (как любой сайт, видит адрес запроса и IP-адрес), личных данных в нем нет; это тоже указывается в политике. Закладка при каждом запуске выполняет на странице формы код, который отдает Worker, поэтому пользователи доверяют оператору бота; это тоже указывается в политике. Страницы с картой загружают карту Mapbox, поэтому браузер посетителя обращается к серверам Mapbox; это указывается в политике. ## Адрес: справочник и территории

Бот определяет адрес по своему справочнику адресов, куда входят и территории; Nominatim — только там, где в пределах 30 м нет ни одного адреса справочника.

93. [сделано] Адреса и названия берутся только из OSM через Nominatim, из обхода владельца (п.98) и из ввода пользователей (п.99). Данные Google и Mapbox не копируются и не обводятся.
94. [сделано] Территория — адрес справочника в форме многоугольника: точки периметра (не меньше 3) и название. Периметры территорий не перекрываются и не выходят за границу района с запасом 50 м. Название территории идет в адрес; почтовый район — по п.33.
95. [сделано] Территории приходят так же, как остальные адреса обхода: владелец рисует многоугольник в файле обхода на geojson.io (п.98), и он проходит входящие адреса и одобрение администратора (п.99). Многоугольник, который выходит за границу района с запасом 50 м или перекрывает другую территорию, при преобразовании файла показывается как подозрительный. Исправить многоугольник можно только через файл обхода.
96. [сделано] Справочник адресов — одна таблица D1, по которой бот определяет адрес. Запись — текст адреса (до 100 символов), вид и форма: точка, линия (одна или несколько) или многоугольник (территория, п.94). Дом с номером и магазин — точка. Улица без номера и длинный дом (многоквартирный, школа) — линия; у длинного дома линии вдоль фасадов со стороны улицы, где стоят машины, у каждой линии свой свободный текст, по которому место найдут, например `Parkside Drive, outside Belmayne Educate Together National School`. Угловой дом с одним адресом — одна линия с поворотом; если у фасадов разные адреса — отдельные линии. Справочник хранится без срока, до удаления администратором. Вид адреса: `house` — дом с номером; `appt` — многоквартирный дом; `facility` — магазин, школа, остановка и подобное; `spot` — место без номера дома (перекресток, улица, ориентир); `area` — территория; вид `temp` бывает только у адреса во входящих (п.99), в справочник адрес попадает уже с настоящим видом. Форма в базе отдельно не хранится, ее задает геометрия; вид `area` бывает только у многоугольника, и многоугольник всегда `area`. У каждого адреса справочника и входящих есть источник `source`: `walk` (обход), `user` (написан пользователем) или `osm` (выгрузка OSM, п.103); адреса, лежавшие в справочнике до появления источника, имеют `walk`; при переносе из входящих источник переходит в справочник, замена старого адреса новым («Keep newN») ставит источник нового адреса.
97. [сделано] Бот берет до двух адресов справочника любой формы, ближайших к точке, но не дальше 30 м; ближайший первым. Расстояние — до точки; до ближайшей точки линии; до многоугольника — 0 внутри него, снаружи — до его границы.
98. [сделано] Обход: владелец идет по району с записью трека в OsmAnd и ставит метки с адресами с табличек и вывесок — на ходу или потом, по фото с координатами места съемки. У длинного дома и у улицы без номера метки ставятся в начале и в конце с одним текстом, линия — отрезок трека между ними. Каждый обход — отдельный файл GeoJSON (`walk-1.geojson`, `walk-2.geojson` и т.д.); он хранится на компьютере владельца и в репозиторий не попадает. Агент преобразует трек GPX в такой файл, ставит вид адреса (`kind`, п.96) и показывает совпадающие тексты и подозрительные точки; с прошлыми файлами он новый не сравнивает: владелец сам знает, где уже ходил. Владелец проверяет файл на geojson.io (линии — только по своему треку). Файл — FeatureCollection; у каждого объекта свойство `address` (текст адреса или название территории, до 100 символов, без почтового района) и `kind` (вид адреса, п.96; `temp` недопустим), форма — по типу геометрии: Point — точка, LineString или MultiLineString — линия, Polygon — территория. Владелец отправляет файл боту кнопкой «Import file» в /admin, и бот кладет его адреса во входящие (п.104). Исправленная линия или территория из прошлого обхода кладется в новый файл с тем же текстом и на экране входящих показывается группой дублей с кнопками «Keep old» и «Keep new1» (п.99). Адреса обхода приходят во входящие неодобренными, без Telegram ID; администратор одобряет их в /admin по одному или все сразу одним действием (текст кнопки предлагает агент, утверждает владелец).
99. [сделано] Входящие адреса — таблица D1: форма, текст адреса, Telegram ID автора (у адресов от пользователей), решение администратора. Адрес от пользователя (п.18, п.19) записывается при выдаче ссылки, форма — точка геолокации репорта. Адрес от пользователя получает вид `temp`; при одобрении администратор выбирает вид (п.96): «Approve» у такого адреса и «Keep newN» в группе дублей открывают экран `Choose the kind` с кнопками по одной в ряду «house», «appt», «facility», «spot» и «Back»; выбор вида сразу решает адрес и показывает следующий входящий, «Back» показывает тот же адрес снова; без вида адрес пользователя одобрить нельзя. У адреса обхода вид берется из файла, «Approve» и «Keep newN» без выбора. Администратор одобряет или отклоняет его в /admin. Тексты решений: черновик предлагает агент, утверждает владелец. Сразу после каждого решения администратора в /admin одобренные адреса переносятся в справочник, отклоненные удаляются, адреса без решения ждут; ночного переноса нет, а адрес, одобренный, но не перенесенный из-за сбоя, переносится при следующем решении в /admin. Дубль — тот же текст (без учета регистра и лишних пробелов), форма которого ближе 5 м к форме такого же адреса справочника: он не переносится и удаляется. Тот же текст дальше — адрес остается во входящих без решения. Адреса с одним текстом решаются как группа дублей (ниже), а не по одному. Telegram ID стирается после решения. Адрес от пользователя без решения стирается целиком через 2 месяца после записи; адреса обхода без решения ждут без срока. Расстояние между формами — наименьшее, 0, если формы пересекаются или одна внутри другой. При переносе дубль проверяется у одобренных адресов, в том числе между адресами, перенесенными за один раз. «Заменить старый новым» (оставить новый адрес группы, когда в справочнике есть такой же текст) заменяет ближайший к новому адрес справочника с тем же текстом, его ID остается прежним; если такого уже нет, новый адрес добавляется.

Экран входящих адресов (кнопка «Incoming addresses» на экране /admin) показывает их по одному, от старых к новым; адреса, по которым уже есть решение, не показываются. Над экраном бот присылает метку на карте Telegram: точку, у линии — ее середину по длине, у территории — середину прямоугольника вокруг нее; метка удаляется вместе с экраном. Текст экрана: `Incoming address 1 of 37`, текст адреса, затем `Point (house), from the walk`, `Point (house), from OSM` или `Point, written by a user` (`Line`, `Area` для линии и территории; в скобках вид адреса обхода или выгрузки OSM); Кнопки: «Approve», «Reject», «Next» в одном ряду, под ними «Approve all from the walk» и «Back», в следующем ряду — «Approve all from OSM». «Approve all from the walk» сразу, без вопроса, одобряет все адреса обхода без решения, кроме тех, чей текст уже есть в справочнике, и тех, чей текст есть у другого адреса без решения (из любого источника); «Approve all from OSM» так же одобряет все адреса OSM без решения. Адреса другого источника ни та ни другая кнопка не трогает. Адреса, которые они пропустили, решаются по одному или как группа дублей. «Next» показывает следующий экран (адрес или группу дублей) без решения, после последнего — первый. «Back» возвращает экран /admin. Если входящих нет — `No incoming addresses` и «Back».

Группа дублей — адреса без решения с одним текстом (регистр и лишние пробелы не считаются) вместе с адресами справочника с таким же текстом, если всего их два и больше. Группа показывается одним экраном на месте первого из ее входящих адресов (счет `1 of 37` идет по экранам), остальные ее адреса при «Next» пропускаются. Над экраном бот присылает по метке с названием на каждый адрес группы: `old` (`old1`, `old2`, если в справочнике таких адресов несколько) для адреса справочника и `new1`, `new2` и так далее для входящих; под названием строка с текстом адреса; метки удаляются вместе с экраном. Текст экрана: `Incoming address 1 of 37`, текст адреса, `Same address, 3 objects` и по строке на каждый адрес группы: `old: Point (house), in the directory`, `new1: Point (house), from OSM`, `new2: Point, written by a user` (форма и вид, как у одиночного экрана). Кнопки по одной в ряду: «Keep old», «Keep new1», «Keep new2» и так далее, затем «Reject all», затем «Next», затем «Approve all from the walk» и «Back» в одном ряду, затем «Approve all from OSM». Нажатая кнопка «Keep …» оставляет этот адрес в справочнике, а остальные адреса группы убираются: другие входящие отклоняются, адреса справочника удаляются; если оставлен входящий адрес, а в справочнике есть адрес группы, входящий заменяет ближайший из них, и ID этого адреса остается прежним (п.99). Для адреса пользователя «Keep newN» сначала открывает экран `Choose the kind` (как у одиночного адреса, «Back» возвращает группу); без вида адрес не остается. Кнопка «Reject all» (под кнопками «Keep») отклоняет все новые адреса группы, адреса справочника остаются; бот показывает следующий экран и убирает пины. «Approve» и «Reject» на экране группы нет. Кнопки экрана группы и открытого из него экрана `Choose the kind` работают только на текущем экране группы: кнопка старого экрана только снимает «часики» (п.17). Команда меню удаляет экран `Choose the kind` группы вместе с пинами группы.

[сделано] Администратор в /admin удаляет и исправляет адреса справочника: текст — сообщением (до 100 символов), точку — новой геолокацией; линии и территории исправляются только через файл обхода; вид адреса (п.96) при исправлении может измениться. Владелец открывает файл на geojson.io, добавляет и правит точки, линии и территории и сохраняет файл. Кнопка «Import file» спрашивает `Send the edited file` с кнопкой «Back»; владелец присылает файл документом (так же присылается файл обхода, п.98). Бот сравнивает файл со справочником и с входящими адресами без решения и кладет во входящие без решения, с источником `walk`, только новые и исправленные адреса (изменился текст, вид или форма; координаты сравниваются с точностью до 6 знаков); адреса, которые уже есть в справочнике или ждут решения во входящих, пропускаются. Адрес, отклоненный или удаленный после выгрузки, при повторной отправке старого файла снова придет во входящие, поэтому перед правкой каждый раз делается свежий «Export directory». Свойство `source` в файле не учитывается: исправленный адрес OSM тоже приходит с источником `walk`. После загрузки бот пишет `Loaded 6 addresses, 270 unchanged skipped` (при одном адресе `Loaded 1 address`) и сразу показывает экран входящих адресов (п.99). Если в файле есть ошибка (нет текста, текст длиннее 100 символов, неверная геометрия, координаты вне допустимых значений, незамкнутый многоугольник или многоугольник с дырами, нет `kind`, вид `temp` или неизвестный вид, `area` не у Polygon или Polygon с другим видом), а также если текст нового или исправленного адреса встречается в справочнике несколько раз или у двух новых и исправленных объектов файла, бот ничего не загружает и пишет `The file has errors, nothing was loaded` и под ним ошибки (сколько помещается в одно сообщение), и ждет файл снова. На другое сообщение, файл не в формате GeoJSON, файл не в кодировке UTF-8 или файл, который не удалось скачать из Telegram, бот отвечает `Send the file as a document` и ждет файл снова. Если вопрос, пока файл скачивался и проверялся, уже отменен («Back», команда) или задан заново, бот этот файл не загружает и ничего не отвечает. Исправленная форма с прежним текстом показывается на экране входящих группой дублей с «Keep old» и «Keep new1» (п.99); смена текста в файле создает новый адрес, текст правится в /admin (п.100). Удалить адрес через файл нельзя: удаление — кнопка «Delete» в /admin.
